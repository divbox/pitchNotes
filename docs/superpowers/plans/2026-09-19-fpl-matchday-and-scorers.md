# FPL/Openfootball Matchday Label & Golden Boot Watch Source Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the stale `WEEK_NUMBER` masthead label with a live "Matchday N" figure sourced from the free Fantasy Premier League (FPL) public API and cross-checked against openfootball/england's public-domain fixture schedule, and move Golden Boot Watch's player goals/assists off football-data.org's scorers-only list onto the same FPL API, which covers every player rather than just those who've already scored.

**Architecture:** Two new small fetch scripts follow this repo's existing one-script-per-source convention (`fetch_data.py` for football-data.org, `fetch_odds.py` for The Odds API): `fetch_fpl.py` (no auth key — public endpoint) supplies the current gameweek number and every player's real goals/assists; `fetch_openfootball.py` (no auth key — public repo) independently derives the current matchday from a plain-text season schedule, used purely as a cross-check. `build.py` wires both in alongside the existing `fetch_data.py` call, which keeps standings (The Table) and Champions League fixtures unchanged. If the two matchday sources disagree, FPL wins and the build keeps going — but it logs a clear WARN line (surfaced through `run_weekly.py`'s existing log file, not silently swallowed) so Div can come back and have it fixed later.

**Tech Stack:** Python 3, stdlib only (`urllib.request`, `json`, `re`, `datetime`) — matches every existing script in `scripts/`. No test framework in this repo; verification is each script's own `--demo` self-check against the live API, same pattern as `fetch_data.py`/`fetch_odds.py`.

**Spec:** This plan's spec is the conversation it came out of — no separate spec doc. The prior decision record is `cadence.md` (repo root), whose "Open items → Reader-facing label" section this plan resolves and which Task 4 retires once resolved.

## Global Constraints

- No new API keys. FPL's `fantasy.premierleague.com/api/bootstrap-static/` and openfootball's raw GitHub file are both public/unauthenticated — verified live during research (curl'd both without credentials).
- The Table (standings) and Champions League fixtures stay on football-data.org. FPL is Premier-League-only and none of the researched sources give a computed standings table for free — that's out of scope here (Div: "FPL API seems like the best answer" for label + scorers specifically, "openfootball...secondary/x-check").
- Editorial sections (Hero, Schedule Watch, Club News, Transfer Wire, Divbox 101) are never auto-generated by `build.py` — confirmed in CLAUDE.md's Pipeline section ("build.py only reads these values -- it never generates prose itself"). FPL's gameweek deadline timestamp is fetched as part of `fetch_fpl.py`'s single API call (it's in the same response, free) but nothing in this plan renders it — it's there for the `pitch-notes-content` skill to consult by hand if useful for Schedule Watch research, not for automated copy.
- Doc updates ship in the same commit as the behavior they describe (Div: "keep the doc updates/code changes in sync/committed").
- Masthead wording: **"Matchday {N}"** — this was cadence.md's candidate wording and nothing in this conversation contradicted it; flagging here as the one label-wording assumption baked into the code below. If Div wants different wording, it's a one-line change in `build.py`'s `TEMPLATE`.
- Mismatch handling (Div's call): if FPL and openfootball disagree on the current matchday number, `build.py` does **not** stop — it uses FPL's number and logs a `MISMATCH` line to stderr naming both values and the date, so Div can have it looked at later without the pipeline halting. Because `run_weekly.py` only writes to `logs/pitch-notes.log` on a step's success/failure line today (a step's stderr is captured but discarded on success), Task 3 also adds a one-line change there so a non-fatal warning actually lands in the log instead of vanishing. If openfootball is unreachable/unparseable (network error, format change), that's the same non-fatal path: log a warning and proceed on FPL alone — the cross-check is a safety net, not a hard dependency for two independent sources to both be up.
- Golden Boot Watch fully switches to FPL — not blended with football-data.org. football-data.org's `/scorers` call, `top_scorers()`, and the `"scorers"`/`"matchday"` keys in `fetch_data.build()` become dead code once nothing reads them and are deleted in the same task (Surgical Changes: "remove orphans").

def get(path):
    req = urllib.request.Request(BASE + path, headers={"User-Agent": "Mozilla/5.0"})
    with urllib.request.urlopen(req) as r:
        return json.load(r)


def current_event(events):
    for ev in events:
        if ev["is_current"]:
            return ev
    for ev in events:
        if ev["is_next"]:
            return ev
    raise RuntimeError("no current or next gameweek in FPL events")


def build_scorers(elements, teams):
    tla_by_team = {t["id"]: t["short_name"] for t in teams}
    return [
        {
            "player": {"name": e["web_name"]},
            "team": {"tla": tla_by_team[e["team"]]},
            "goals": e["goals_scored"],
            "assists": e["assists"],
        }
        for e in elements
    ]


def build():
    data = get("/bootstrap-static/")
    event = current_event(data["events"])
    return {
        "gameweek": event["id"],
        "deadline": event["deadline_time"],
        "scorers": build_scorers(data["elements"], data["teams"]),
    }

The expected matchday numbers below are real, verified against the live file at research time (`raw.githubusercontent.com/openfootball/england/master/2026-27/1-premierleague.txt`): Matchday 1 opens Fri Aug 21 2026, Matchday 19 is the first fixture after the file's one internal year rollover (Fri Jan 1 2027), Matchday 38 (the finale) is Sun May 30 2027.

```python
"""Cross-check the current PL matchday against openfootball/england's
plain-text season schedule (public domain, no key -- confirmed reachable
without auth). A second, independent source so fetch_fpl.py's gameweek
number is never trusted alone for something CLAUDE.md's data rules treat
as a schedule fact.

Format reference (one block per matchday, exactly 2-space-indented date
lines, year only stated where it changes -- confirmed against the live
2026-27 file):

    ▪ Matchday 1
      Fri Aug 21 2026
        20:00  Arsenal FC v Coventry City FC  3-0 (2-0)
      Sat Aug 22
        ...

Usage: python3 fetch_openfootball.py [YYYY-MM-DD]  (defaults to today)
"""
import datetime
import re
import sys
import urllib.request

RAW_BASE = "https://raw.githubusercontent.com/openfootball/england/master"
MATCHDAY_RE = re.compile(r"^▪ Matchday (\d+)\s*$")
DAY_RE = re.compile(r"^  (\w{3} \w{3} \d{1,2})(?: (\d{4}))?\s*$")
SEASON_START_MONTH = 6  # PL season runs Aug-May; anything before June still belongs to the prior season


def demo():
    """ponytail: parse the real file, check known matchday boundaries."""
    text = fetch_season_text(2026)
    assert matchday_for_date(text, datetime.date(2026, 8, 21), 2026) == 1, \
        "season opener should be Matchday 1"
    assert matchday_for_date(text, datetime.date(2027, 1, 1), 2026) == 19, \
        "New Year's Day fixture should be Matchday 19 (tests the year-rollover parse)"
    assert matchday_for_date(text, datetime.date(2027, 5, 30), 2026) == 38, \
        "season finale should be Matchday 38"
    print("demo OK", file=sys.stderr)


if __name__ == "__main__":
    if len(sys.argv) > 1 and sys.argv[1] == "--demo":
        demo()
    else:
        target = (
            datetime.date.fromisoformat(sys.argv[1])
            if len(sys.argv) > 1
            else datetime.date.today()
        )
        print(current_matchday(target))
```

def season_start_year(d):
    return d.year if d.month >= SEASON_START_MONTH else d.year - 1


def fetch_season_text(start_year):
    season = f"{start_year}-{str(start_year + 1)[-2:]}"
    url = f"{RAW_BASE}/{season}/1-premierleague.txt"
    req = urllib.request.Request(url, headers={"User-Agent": "Mozilla/5.0"})
    with urllib.request.urlopen(req) as r:
        return r.read().decode()


def matchday_for_date(text, target_date, initial_year):
    """Most recently *started* matchday as of target_date -- matches FPL's
    is_current semantics, which flips at the round's first kickoff, not
    once every fixture in it has finished."""
    matchday = None
    year = initial_year
    best = None
    for line in text.splitlines():
        md = MATCHDAY_RE.match(line)
        if md:
            matchday = int(md.group(1))
            continue
        day = DAY_RE.match(line)
        if not day:
            continue
        if day.group(2):
            year = int(day.group(2))
        day_date = datetime.datetime.strptime(f"{day.group(1)} {year}", "%a %b %d %Y").date()
        if day_date <= target_date:
            best = matchday
        else:
            break
    return best


def current_matchday(target_date):
    start_year = season_start_year(target_date)
    try:
        text = fetch_season_text(start_year)
    except (urllib.error.URLError, OSError):
        return None
    return matchday_for_date(text, target_date, start_year)
```

def run(steps):
    for name, cmd in steps:
        result = subprocess.run(cmd, capture_output=True, text=True)
        if result.returncode != 0:
            err = result.stderr.strip().splitlines()[-1] if result.stderr.strip() else "unknown error"
            log(f"FAILED at {name}: {err}")
            print(f"Stopped: {name} failed (exit {result.returncode}).", file=sys.stderr)
            print(result.stderr, file=sys.stderr)
            return result.returncode
        if result.stderr.strip():
            for line in result.stderr.strip().splitlines():
                log(f"WARN {name}: {line}")
        log(f"OK {name}")
    log("SUCCESS full run")
    print("Weekly run complete.")
    return 0
```
